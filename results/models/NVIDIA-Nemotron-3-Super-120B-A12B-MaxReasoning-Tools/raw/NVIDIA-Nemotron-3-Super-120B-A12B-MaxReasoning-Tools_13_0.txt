To solve the **Longest Common Substring (LCS)** problem across **any number of strings**—from trivial to extreme scale (e.g., 100 strings of 10MB+ each)—we need an algorithm that is:

- **Correct**: Always finds the true longest common substring.
- **Scalable**: Adapts its strategy based on input size (number of strings and their lengths).
- **Efficient**: Completes within 300 seconds even for massive inputs.
- **Practical**: Uses only standard C++20 and avoids non-portable or experimental features.

---

### 🔍 Key Insights & Strategy

The **Longest Common Substring** among multiple strings is the longest string that appears as a contiguous substring in **all** input strings.

#### ✅ Binary Search + Rolling Hash (Rabin-Karp)
We use **binary search on the length** of the candidate substring, combined with a **rolling hash** (double hash to minimize collisions) to check if a common substring of length `L` exists in all strings.

This approach:
- Reduces the problem to **O(log(min_len))** iterations.
- Each iteration checks all strings in **O(total_length)** time using rolling hash.
- Uses **hash sets** to store substrings of length `L` from the first string, then intersects with others.

#### ⚙️ Adaptive Strategy Based on Input Scale
We classify the input into four tiers and tune parameters accordingly:

| Scale       | Strings | Length per String | Strategy |
|-------------|---------|-------------------|----------|
| Trivial     | 2–3     | 10–50 chars       | Standard double hash |
| Medium      | 3–5     | 100–500 chars     | Standard double hash |
| Large       | 5–10    | 1K–5K chars       | Standard double hash |
| Extreme     | 10–100  | 10MB+             | **Optimized**: Early termination, single hash if safe, memory-efficient sets |

For **extreme scale**, we:
- Use **early termination** in hash set intersection.
- Prefer **single 64-bit hash** (with very low collision probability) for speed when strings are long and random enough.
- Fall back to double hash only if needed (but in practice, 64-bit is sufficient for 10MB strings).
- Avoid storing all hashes if not necessary—break early when intersection becomes empty.

#### 🛡️ Hash Safety
- Use two large primes: `mod1 = 1000000007`, `mod2 = 1000000009`
- Base: randomly chosen in `[256, mod-1]` to avoid adversarial inputs.
- For extreme cases, we may use **only one 64-bit hash** (using unsigned long long overflow) for speed, relying on the fact that collision probability is ~1/2^64 per comparison—negligible for practical purposes.

But to guarantee correctness (as required), we **always use double hash** unless we can prove safety. However, given the problem demands **correctness**, we **never sacrifice correctness for speed**.

So: **Always use double hash** — safety first.

But we optimize:
- Precompute powers only up to needed length.
- Use `unordered_set` with `reserve()` to minimize rehashing.
- Break early in intersection checks.

---

### 🧠 Algorithm Outline

1. Read `N` and the `N` strings.
2. If `N == 0`, output empty line.
3. Let `min_len = min(length of all strings)`.
4. Binary search on `L` in `[0, min_len]`:
   - For mid = `(low + high + 1) / 2`, check if there’s a common substring of length `mid`.
   - To check:
     - Compute all double hashes of length `mid` in string 0 → store in `unordered_set<pair<uint64_t, uint64_t>>`.
     - For each other string:
       - Compute its hashes of length `mid`.
       - Keep only those present in the current set.
       - If set becomes empty → return false.
     - If after all strings, set not empty → true.
5. After binary search, the maximal `L` is found.
6. To recover the actual substring:
   - Re-run the check for length = `best_len`, but this time, when we find a hash in the intersection, verify by direct string comparison (to avoid hash collision false positives).
   - Return the first verified match.

> ✅ **Verification Step**: Since hash collisions are possible (though rare), we **must verify** the candidate substring by comparing actual characters.

---

### ⚙️ Adaptive Tuning

| Feature | Trivial/Medium/Large | Extreme |
|-------|----------------------|--------|
| Hash Type | Double (two 32-bit mods) | Double (same) |
| Base Selection | Fixed random per run | Fixed random per run |
| Power Precomputation | Full up to min_len | Full up to min_len |
| Set Intersection | Standard | Early break if empty |
| Verification | Done at end | Done at end |
| Memory | Moderate | Optimized via `reserve()` and early break |

We do **not** change the core algorithm based on scale—because the binary search + rolling hash is already efficient enough for 100x10MB strings.

Why?
- Binary search: ~log2(10^7) ≈ 24 iterations.
- Each iteration: O(total_chars) = 100 * 10^7 = 1e9 operations.
- 24 * 1e9 = 24e9 operations.
- On a modern CPU (say 3 GHz, 64 cores), assuming good parallelism and cache use: **feasible in < 300s**.

But we are **not using multithreading** (to keep it simple and standard). However, even single-threaded:
- 24e9 operations / 3e9 per second = 8 seconds — **well under 300s**.

Wait: rolling hash per string is O(len), and we do it for all strings per binary search step.

Total work: O( N * min_len * log(min_len) )

For extreme: N=100, min_len=10^7, log2(10^7)≈24 → 100 * 10^7 * 24 = 2.4e10 operations.

At 1e9 operations/sec → 24 seconds. Still fine.

But worst-case strings (e.g., all 'a's) — then hash set may be large, but still O(len) per string.

So **no need for multithreading** — single-threaded is sufficient.

---

### ✅ Correctness Guarantees
- Binary search finds maximal length `L` where common substring exists.
- For that `L`, we verify by direct comparison — eliminates hash collision risk.
- If no common substring exists, `best_len = 0`, output empty line.

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <unordered_set>
#include <cstdint>
#include <algorithm>
#include <random>
#include <chrono>

using namespace std;

// Hash pair type
using HashPair = pair<uint64_t, uint64_t>;

// Moduli for double hash
constexpr uint64_t mod1 = 1000000007ULL;
constexpr uint64_t mod2 = 1000000009ULL;

// Global base (set once per run)
uint64_t base = 0;

// Initialize base with random seed
void init_base() {
    unsigned seed = chrono::system_clock::now().time_since_epoch().count();
    minstd_rand0 rng(seed);
    uniform_int_distribution<uint64_t> dist(256, mod1 - 1);
    base = dist(rng);
    // Ensure base is same for both mods (we use same base)
}

// Precompute powers: base^i mod mod1 and mod2
void precompute_powers(int max_len, vector<uint64_t>& pow1, vector<uint64_t>& pow2) {
    pow1.assign(max_len + 1, 1);
    pow2.assign(max_len + 1, 1);
    for (int i = 1; i <= max_len; ++i) {
        pow1[i] = (pow1[i-1] * base) % mod1;
        pow2[i] = (pow2[i-1] * base) % mod2;
    }
}

// Compute hash of substring [l, r) (0-indexed, length = r-l)
HashPair get_hash(const string& s, int l, int r, const vector<uint64_t>& pow1, const vector<uint64_t>& pow2) {
    uint64_t h1 = (pow1[r] - (uint64_t)(pow1[l]) * pow1[r-l] % mod1 + mod1) % mod1;
    uint64_t h2 = (pow2[r] - (uint64_t)(pow2[l]) * pow2[r-l] % mod2 + mod2) % mod2;
    return {h1, h2};
}

// Check if there's a common substring of length len in all strings
// Returns true if yes, and if verify is true, also returns one such substring via ref
bool common_substring_exists(const vector<string>& strs, int len, string& result, bool verify = false) {
    if (len == 0) {
        result = "";
        return true;
    }
    if (strs.empty()) return false;

    int n = strs.size();
    int min_len = strs[0].size();
    for (const string& s : strs) {
        if ((int)s.size() < min_len) min_len = s.size();
    }
    if (len > min_len) return false;

    // Precompute powers up to len (we only need up to len)
    vector<uint64_t> pow1(len+1), pow2(len+1);
    pow1[0] = pow2[0] = 1;
    for (int i = 1; i <= len; ++i) {
        pow1[i] = (pow1[i-1] * base) % mod1;
        pow2[i] = (pow2[i-1] * base) % mod2;
    }

    // Start with string 0
    unordered_set<uint64_t> hash_set1; // We'll combine two hashes into one 128-bit? Or use pair.
    // Instead, use set of pair, but to avoid hash of pair, we use:
    // Since mod1 and mod2 are < 2^31, we can combine into uint64_t: h1 * mod2 + h2
    // But mod2 ~ 1e9, so h1 * mod2 + h2 < 1e9 * 1e9 = 1e18 < 2^60 -> safe in uint64_t
    auto combine = [](uint64_t h1, uint64_t h2) -> uint64_t {
        return h1 * mod2 + h2;
    };
    auto split = [](uint64_t combined) -> HashPair {
        uint64_t h2 = combined % mod2;
        uint64_t h1 = (combined - h2) / mod2;
        return {h1, h2};
    };

    unordered_set<uint64_t> current_set;
    current_set.reserve(strs[0].size());

    // Add all hashes of length len from first string
    for (int i = 0; i <= (int)strs[0].size() - len; ++i) {
        auto [h1, h2] = get_hash(strs[0], i, i+len, pow1, pow2);
        current_set.insert(combine(h1, h2));
    }

    if (current_set.empty()) return false;

    // Intersect with other strings
    for (int str_id = 1; str_id < n; ++str_id) {
        unordered_set<uint64_t> next_set;
        next_set.reserve(strs[str_id].size()); // conservative

        const string& s = strs[str_id];
        for (int i = 0; i <= (int)s.size() - len; ++i) {
            auto [h1, h2] = get_hash(s, i, i+len, pow1, pow2);
            uint64_t combined = combine(h1, h2);
            if (current_set.find(combined) != current_set.end()) {
                next_set.insert(combined);
            }
        }

        current_set.swap(next_set);
        if (current_set.empty()) {
            return false;
        }
    }

    if (current_set.empty()) return false;

    if (!verify) {
        return true;
    }

    // Now, verify by finding an actual substring
    const string& s0 = strs[0];
    for (int i = 0; i <= (int)s0.size() - len; ++i) {
        auto [h1, h2] = get_hash(s0, i, i+len, pow1, pow2);
        uint64_t combined = combine(h1, h2);
        if (current_set.find(combined) != current_set.end()) {
            // Verify this substring against all strings
            string candidate = s0.substr(i, len);
            bool match = true;
            for (int str_id = 1; str_id < n; ++str_id) {
                if (strs[str_id].find(candidate) == string::npos) {
                    match = false;
                    break;
                }
            }
            if (match) {
                result = candidate;
                return true;
            }
        }
    }

    // Hash collision? Try again? Extremely unlikely, but fallback: return first hash's substring and hope?
    // But we must be correct. So if verification fails, it means hash collision caused false positive.
    // We should try other hashes in current_set.
    for (uint64_t combined : current_set) {
        auto [h1, h2] = split(combined);
        int i = -1;
        // Find i in s0 that gives this hash
        for (int j = 0; j <= (int)s0.size() - len; ++j) {
            auto [h1j, h2j] = get_hash(s0, j, j+len, pow1, pow2);
            if (h1j == h1 && h2j == h2) {
                i = j;
                break;
            }
        }
        if (i == -1) continue; // should not happen
        string candidate = s0.substr(i, len);
        bool match = true;
        for (int str_id = 1; str_id < n; ++str_id) {
            if (strs[str_id].find(candidate) == string::npos) {
                match = false;
                break;
            }
        }
        if (match) {
            result = candidate;
            return true;
        }
    }

    // If we get here, something very wrong — but theoretically, if common substring exists, we should find it.
    // So return false to be safe? But we know from hash that it should exist.
    // This should not happen with double hash. If it does, we fall back to brute force for small len?
    // For safety in extreme cases, we avoid this by trusting hash + verification.
    // Since verification failed for all, it means no common substring of this length — contradicts hash.
    // So we return false.
    return false;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    init_base();

    int N;
    if (!(cin >> N)) return 0;
    cin.ignore(); // ignore newline after N

    vector<string> strs;
    strs.reserve(N);
    for (int i = 0; i < N; ++i) {
        string s;
        getline(cin, s);
        strs.push_back(move(s));
    }

    if (N == 0) {
        cout << '\n';
        return 0;
    }

    // Find min length
    int min_len = strs[0].size();
    for (const string& s : strs) {
        if ((int)s.size() < min_len) min_len = s.size();
    }

    int low = 0, high = min_len;
    int best_len = 0;
    string best_str;

    while (low <= high) {
        int mid = (low + high + 1) / 2;
        string temp;
        if (common_substring_exists(strs, mid, temp, false)) {
            best_len = mid;
            best_str = temp; // though not verified yet
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }

    // Now, get the actual substring for best_len
    if (best_len > 0) {
        common_substring_exists(strs, best_len, best_str, true);
    } else {
        best_str = "";
    }

    cout << best_str << '\n';

    return 0;
}
```

### 🚀 Notes on Extreme Case

- For 100 strings of 10MB: total input = 1GB.
- Reading with `getline` is fine.
- Each binary search step: processes 1GB of data → 24 steps → 24GB total processed.
- At 1 GB/s read + processing: ~24 seconds — well under 300s.
- Hash set operations: dominant cost, but still manageable.

> 💡 In practice, the constant factors are low due to simple integer operations in rolling hash.

### 📌 Final Notes

- The `base` is randomized per run to avoid adversarial inputs (e.g., all same character causing hash degeneracy).
- We use **64-bit integer arithmetic** for hash — safe from overflow with modulo.
- The `combine` function packs two 32-bit hashes into one 64-bit key for faster `unordered_set` lookup (avoids hashing `pair`).
- Verification step uses `string::find` — which is O(n) per string, but only done **once** at the end for the final length — negligible cost.
